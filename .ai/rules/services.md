# Services

## Strict Isolation and Mandatory Developer Verification for System & Security Module
The System Tables & Security Explorer module is strictly private, confidential, and security-critical. It must remain quarantined and never mixed with standard application pages or features. Any modifications or additions must be under direct developer supervision: the AI MUST ask the developer whether the addition belongs to this private security module before making changes:
> *"هل هذه الإضافة تنتمي إلى هذا الملف/القسم الأمني السري أم لا؟"*

## Mandatory Comprehensive Ecosystem Synchronization Upon Adding or Modifying Services
Whenever creating or modifying any service:
1. **Trilingual Localization:** All user-facing exception messages, status responses, or event descriptions generated by the service must be authored in English as master keys in `__('...')` and simultaneously synchronized across `lang/en.json`, `lang/ar.json`, and `lang/fr.json` (1-to-1 parity, 0 non-English keys).
2. **Audit Trail & Forensics:** All domain mutations executed by the service must be recorded in Spatie's `activity_log` (`causedBy`, `performedOn`, `properties`). Any new activity description pattern must be registered in `SystemTableService::translateActivityDescription()` with regex matchers and trilingual translations.
3. **Notifications & Alerts:** If the service triggers notifications or dispatch events, it must use the structured `SystemActivityAlert` schema and scope by the 3 functional tiers (Management, Engineering, Technicians).
4. **Automated Verification:** Any service logic must be covered by automated feature tests, formatted via `vendor/bin/pint --dirty --format agent`, and documented in `docs/changelog.md`, `docs/project_state.md`, and `docs/ARCHITECTURE_LOG.md`.
